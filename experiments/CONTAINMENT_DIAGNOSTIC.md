# 包含森林结构诊断（第一阶段）

状态：2026-09-12，工具已编译，本机合成小图测试通过；未运行真实数据集。
这是查询无关的索引结构原型和诊断，不是已完成的新在线聚类算法，不报告加速比。

## 已经验证到哪一步

独立集合模型检查了 512 种三行邻接关系与 4 种后缀的组合，共 2,048 组，覆盖失活、集合折叠和保持分离的情况。
对每组检查邻域包含、相似度判定、加权核心下界，以及任意活跃核心类选择下的最近核心祖先连接。
另有包含链、等价类、菱形偏序、跨分支和失活反例。

C++ 构建器与独立暴力父类选择模型比较了 67 个小图，每图检查关系的正反两个方向，涵盖全部 3×2 布尔关系、包含链、菱形以及零目标顶点。
同时验证父指针、类权重、代表顶点、Euler 祖先标签、统计值、实际文件字节数和拒绝覆盖已有目录。
加上服务器脚本的数据复用、输入指纹、损坏报告拒绝检查，共 9 项 unittest 全部通过。

这些是有限模型检验，不代替一般性证明，也不证明真实数据上的覆盖率。

## 证书的成立条件与限制

设首关系邻接集合为 A(u)，查询为非独立模型的对称元路径 P=H·H逆。

1. 若 A(u) 包含于 A(v)，沿相同后缀取可达集合的并，仍有 H(u) 包含于 H(v)。
2. 只有当较小端 H(u) 非空时，u、v 才必然互为 P 邻居。此时任何与 H(u) 相交的半路径集合也与 H(v) 相交，所以闭邻域 N[u] 包含于 N[v]。
3. 因而令 du=|N[u]|、dv=|N[v]|，相似度为 sqrt(du/dv)。判断是否达到 ε 只需精确整数度数比，不需要求交。
4. 同一非空首关系等价类具有相同半路径可达集合；活跃时可用类权重计数。查询失活时，各顶点只有自身，不能把该类当成团。
5. 同类及森林祖先/后代中满足阈值的顶点权重，给出相似邻居数的下界。达到论文 μ 可证明核心；没达到不能证明非核心。
6. 在所有核心类已正确确定之后，连接相似的最近核心祖先足以保持“森林可比核心对”子图的连通分量。理由是链上闭度数单调，任一相似祖先/后代之间的核心子链也均满足度数比条件。
7. 这不保证整个核心图连通性：跨分支、跨树连接，未被证明的核心以及非核心归属、hub/outlier 仍需精确处理。

本轮测试一度把“某端活跃”错误当成“两端均可使用无向可比证书”，穷举用例发现后已补齐双方活跃条件。例如首关系 {0} 包含于 {0,1}，但后缀只允许 1 继续时，较小端失活，不能套用度数比公式。
该修正没有更改问题定义，只限定证书何时可以使用；失活/未覆盖情况不能忽略。

非对称闭合元路径不在上述邻域推理覆盖范围。本工具虽然能分别处理所有原始关系方向，但这不等于已解决所有合法查询的在线算法。

## 离线原型保存什么

每种原始关系分别处理正反方向，不枚举任何元路径：

- 对非空邻接集合精确去重，形成带权类。
- 每个类最多选择一个最小基数严格超集作为父类，平局按确定性类 ID 处理。
- 通过稀有元素的倒排类列表找候选，并逐个精确验证包含，不保存全部包含对。
- 保存非空行到类的稀疏映射，以及代表顶点、权重、父类、深度和 Euler 标签。
- 空行不写映射；既不保存各元路径投影边，也不保存相似度表。

文件名 relation-R-D.rcf。D=0 是正向，D=1 是反向。
当前固定编码每个关系方向的字节数为：

    56 + 8 × 非空行数 + 24 × 等价类数

这是附加森林结构，不含运行在线查询仍需要的基础图。文件以 RCFORE01 开头，均为小端整数。
全部关系方向的非空行数不超过两倍去重原始边数，因此该原型空间是线性的，不随元路径组合数增长。
线性不自动意味着常数合理：最坏附加结构可达到约 64 字节/原始边，另有每关系头部。需要测量真实数据后判断是否值得，不应把“不爆炸”写成“很小”。

单父选择会丢失部分真实包含关系；例如 {0} 同时包含于 {0,1} 与 {0,2}，只选一个父类后，另一支不再属于森林证书范围。
找父类的时间也不保证线性；结构稀疏但候选很多时，构建仍可能很慢。工具保留候选数和二分比较计数来识别这种情况。

## 服务器如何运行

在项目根目录执行：

    python3 -B experiments/run_server_containment.py

脚本固定测试 Yelp、IMDB large、Foursquare，每个数据集仅一次，不接收元路径、ε、μ，也不新增算法调参项。
自动编译独立目标、运行小图测试、优先复用已存在的规范化输入；必要时调用原有无损格式转换器。
不会调用被暂停的旧性能计时函数，也不会重新计算历史加速比。

默认使用项目中的 data 和 server-results。沿用已有运维环境变量 DATA_ROOT、RESULT_ROOT、BUILD_DIR、BUILD_JOBS、LIMIT_SECONDS；后两者默认 2 和 7200 秒。
超时是外部进程保护，不是算法截断阈值。超时/失败不会标成完整构建成功。
Linux 脚本依赖现有 CMake、C++17 编译器、Python3、/usr/bin/time 和 timeout；整个 Linux 流程尚未在此 Windows 本机执行。

结束后把脚本打印的 .tar.gz 文件传回即可。压缩包只含 JSON 报告和日志，不含数据集或 .rcf 森林文件；后两者留在服务器。
输入规范化文件会做前后 SHA256 校验。若需转换大数据格式，会产生服务器磁盘和内存开销，但不在本机执行。

## 这一组结果能回答什么

- 各关系方向有多少相同行、父边、包含链，以及加权类内/祖先后代顶点对。
- 分组、父类搜索、标签构建各自耗时；森林实际文件大小。
- 离线计算时间包含从缓冲边构造基础邻接以及森林构建，不含读原始文本、写结果文件。
- 峰值 RSS 包括图和构建临时空间，不能当成离线索引大小。
- 附加森林字节与规范化文本输入字节的比例；这不是完整索引/二进制图的比例。

这组结果不能回答“在线节省了多少昂贵检查”：没有输入查询，也没有在线调用轨迹。
加权可比顶点对数只是结构潜力，不是实际工作覆盖率，更不是时间加速比。

若结构潜力和构建成本值得继续，下一阶段再把证书接入只读在线诊断，统计它在实际 pSCAN 必须执行的检查中覆盖多少；排除已被度数界或连通性跳过的检查，计入查询准备、度数计算与补算成本。
覆盖充分后才实现完整在线算法。完整性能比较还需要迁移重构 HINSCAN 基线的参数及角色计算计时。
