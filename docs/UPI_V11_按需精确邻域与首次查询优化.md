# V11：按需精确邻域与首次查询优化

最终验收：IMDB 首次查询 7.769 → 3.590 s（2.16×），Yelp 122.105 → 65.889 s（1.85×，单次探索结果），详见第 9 节。当前代码采用共享的精确邻域缓存、有限因子对区间复用与缓存压力下的流式提前终止。本轮尚未达到数量级加速。

日期：2026-09-05。本轮以无覆盖阈值、离线仅知道 HIN 与 schema 为主线；没有实现 V10 文档末尾提出的全量类计数方案。V10 中关于“必须预计算全部类计数”的表述只能视为当时的猜想，不是已证明的必要条件。第 4–6 节保留第一轮未共享缓存的测量，最终共享版结果另列，不能混用版本。

## 1. 本轮改动

1. 原邻域缓存主要接纳左端顶点，很多右端顶点仍然重复展开倒排表。现在两端都按需进入查询内 LRU 缓存。
2. 邻域仍是精确集合，自动选择整数列表、稀疏位图或稠密位图。相似性判断使用精确集合交集；支持时使用 CPU POPCNT，否则使用可移植回退。没有哈希近似、误差阈值或预先保存的相似度。
3. 首次构建临时 FLI 时，半路径展开改为访问标记去重，精确度数计算由堆归并改为标记计数。度数、因子关系和度数排序不变。
4. pSCAN 的 sd/ed 剪枝、核心处理顺序、并查集合并、非核心挂载逻辑不变。替换的是邻域访问和精确相似性判断的执行方式。
5. 新增只读 BRI 查询入口，强制只读取基础关系索引，杜绝实验误命中历史目录中的 T-SECI、SCI 或其他路径缓存。
6. Yelp 暴露逐顶点缓存抖动后，进一步让半路径因子列表完全相同的顶点共享一条缓存记录。哈希只用于分组，必须完整比较因子列表；非空相同因子的闭邻域必然相同。空因子顶点不能共享，因为各自闭邻域为不同的单点集合。同因子的两个端点还可直接判定闭邻域交集等于度数。此优化仅合并缓存记录，不把 pSCAN 改成类级聚类。
7. 在同一缓存额度内划出至多 1/16（且至多 65,536 条）的直接映射表，复用因子对已证明的公共邻居数区间。哈希槽冲突只淘汰记录，查找仍检查完整的因子对键。32 MiB 总额度时该表为 1.5 MiB，邻域保留额度为 30.5 MiB；不是额外扩大永久索引，也没有离线计算全量边相似度。
8. 缓存淘汰频繁且命中不足时，对未缓存的右端改用流式精确检查，不强制恢复并缓存完整邻域。已发现交集 c、已访问不同顶点 s、闭邻域度数 d，则交集上界为 c+d-s；c 已达到要求时接受，上界不足时拒绝。缓存记录命中时继续走缓存，左端仍可进入缓存。执行策略不影响相似边或 pSCAN 调度。

区间复用的正确性：若已知交集数 C 满足 L ≤ C ≤ U，要求 t ≤ L 可直接接受，t > U 可直接拒绝，否则继续精确计算。列表提前终止时，已见交集数为 c、未扫描列表长度为 r，则可记录 [c, c+r]；完整求交得到 [c,c]。因此缓存并非把某次 epsilon 的布尔答案用于所有 epsilon。独立测试特意对同一顶点对连续改变 t，验证上下界复用。

## 2. 当前主线的输入输出和存储边界

离线：HIN + schema → 一份 `base.bri`。BRI 保存分类型双向邻接关系，规模由图的顶点、边决定，不随元路径组合数增加。

在线：BRI + 对称元路径 + epsilon + mu → 临时构建 FLI → 按 pSCAN 逻辑按需访问精确邻域 → 簇、顶点角色。

在线不写入 FLI、同构邻接图、边相似度表或路径缓存。临时 FLI 和邻域缓存随查询进程释放。当前实现仍只支持既有的对称元路径范围，不是任意非对称路径实现。

缓存默认保留至多 32 MiB 的邻域记录及其数组容量与因子对区间表；这是执行资源设置，不改变结果，也不是 coverage-floor。它**不是进程总内存上限**：还需要目录、临时位图、可能超预算的单条临时邻域、因子分组的临时排序数组、FLI、pSCAN 状态、在线证书表和分配器开销。IMDB 第一版缓存目录及工作位图约 1.63 MB，共享版再增加约 0.40 MB 的代表映射；原时间戳工作区约 1.20 MB，在线证书表约 37.75 MB，均须另计。本轮未完整测量进程峰值内存。

可预建单条 FLI 的入口保留作消融对照；它需要提前指定元路径，不能拿它的查询时间冒充“离线不知道元路径”的主方案。

## 3. 计时口径

- 同一本机 Release 构建；所有计时程序串行执行，没有并发跑两个算法。
- 完整在线时间使用外部墙钟，包含进程启动、加载、计算、结果写出及退出。
- 旧 HINSCAN 是本项目的**同构图物化 + 未修改上游 pSCAN**复现流程，不是官方 HINSCAN 源码；每轮重新构图，不能只计算已有同构图上的 pSCAN。
- 旧流程写簇；新流程同时写簇和角色，没有为新方案省略结果写出。
- “首次查询”表示没有预建的元路径索引或历史结果，不代表清空操作系统磁盘缓存。操作系统文件缓存未清空。
- DBLP、Movies、IMDB 各 3 次，主表取中位数；Yelp 单次结果单独标注。索引版本在偶数轮反向执行，缓解固定执行顺序影响。
- 表中 MB 按 1,000,000 字节；MiB 按 1,048,576 字节。

最小 DBLP 没有证明新邻域引擎优于旧引擎，存在约 1.8 ms 的中位数回退；不能泛称所有图都加速。该规模下数毫秒差异也容易受启动和调度干扰。

IMDB 的精确检查次数仍是 2,014,602，候选生成次数仍是 270,579；并非少算了边。原引擎右侧相似性展开读取 326,500,580 个倒排条目，另外扫描已有缓存列表 1,024,299,697 个条目。新引擎所有缓存缺失的邻域生成共读取 26,873,809 个倒排条目，精确求交处理 320,577,704 个“列表条目或位图字”。这两类单位不能混同：一个位图字可同时处理 64 个顶点位置。

本轮缓存命中 2,051,739 次、缺失 133,405 次、淘汰 50,277 次。收益主要来自减少右端重复展开、压缩求交操作量，而非修改 pSCAN。

## 6. 首次建图瓶颈处理到什么程度

IMDB 首次 BRI 查询第二轮分阶段：

| 阶段 | 时间 |
|---|---:|
| BRI 加载、路径解析 | 34.959 ms |
| 临时 FLI 构建 | 76.847 ms |
| 其中半路径关系 | 30.698 ms |
| 其中精确度数 | 37.801 ms |
| 其中倒排度数排序 | 8.342 ms |
| pSCAN 调用（含内部初始化与释放） | 3,563.030 ms |
| 其中剪枝与队列初始化 | 383.908 ms |
| 其中核心判定、合并 | 2,717.840 ms |
| 其中非核心处理及结果组织 | 436.334 ms |
| 结果写出 | 40.972 ms |

子阶段不可重复相加。邻域生成约 182.366 ms 已包含在 pSCAN 阶段，不是额外时间。外部时间比内部阶段和略大，因为还计进程启动和退出等。

同轮旧流程同构图物化本身为 1,895 ms，尚不包含输出图的开销。现在无需生成并写出完整同构邻接表，临时 FLI 只需约 77 ms；这一部分确实明显减轻。**但没有消除元路径邻域展开的全部计算**：精确度数仍遍历相关倒排表，聚类仍会按需恢复邻域，并处理百万级不确定边。

旧、新 FLI 构建器从文本读入并写索引的端到端中位数：IMDB 741.174 → 302.896 ms。第二轮纯构建 507 → 96 ms。两份新生成的 FLI 文件均为 5,719,480 B，SHA-256 完全一致。它们是 v2 格式；消融表使用的是原有 4,297,608 B 的 v1 文件，不应混报大小。

因此，本轮改善的是实际执行效率，尚未证明最坏情况下避免投影规模相关工作，更未达到几个数量级的总查询加速。下一热点是 pSCAN 的核心阶段，而不再是 IMDB 上的临时 FLI 构建。

## 7. 正确性与复现

- 10 个确定性/随机小 HIN，分别查询 A-B-A 与 A-B-A-B-A；覆盖空图、孤立点、密集邻域、稀疏邻域、非 64 对齐顶点数。
- 独立参考直接遍历完整元路径，用集合生成闭邻域，不调用 FLI 的半路径展开或度数计数代码。
- 直接以整数比较判定相似边，再计算核心、核心连通分量、非核心归属和角色，作为独立聚类参考。
- 缓存预算为 0、1、96、1024、1048576 字节；四种 epsilon、四种 mu（含大于顶点数的 mu）。新旧访问引擎共 3,200 组结果通过；16,022,760 次精确谓词通过；覆盖了 1,327,099 次淘汰。
- 实测主表的每次新查询簇文件均与本轮重新运行的上游 pSCAN 逐字节一致；角色文件与改前的 pSCAN-on-FLI 逐字节一致。上游 pSCAN 本身不输出本项目的角色文件，不应宣称直接与其角色文件比较。

复现入口（在项目根目录执行）：

```powershell
# 离线仅有图与 schema，不指定元路径和聚类参数
build-cmake/bin/bri_build_index.exe data/raw/hin_text/imdb_legacy experiments/v11/reproduce/base.bri

# 每次均为无路径缓存的首次查询，不持久保存任何 FLI
build-cmake/bin/bri_query_index.exe experiments/v11/reproduce/base.bri A-M-D-M-A 0.5 5 experiments/v11/reproduce/result

build-cmake/bin/verify_adaptive_fli.exe experiments/v11/fixtures
experiments/benchmark_v11.ps1
experiments/benchmark_v11.ps1 -Datasets yelp -Repeats 1
experiments/validate_v11.ps1
```

Yelp 使用原先整理好的 `data/derived/normalized/yelp`。原始文本的 U、R 顶点数各少声明 1，直接使用会被读取器拒绝；本轮没有修改原始数据或重新解释顶点。

原始记录：`experiments/v11/timing-*.csv`、`summary-*.csv`、`benchmark/<dataset>/*.log`、`adaptive-correctness.log`。改前二进制保存在 `experiments/v11/*_before.exe`，便于同环境消融；它们不会参与默认查询。

## 8. 失败实验：Yelp 不共享因子的逐顶点缓存

Yelp U-R-B-R-U，epsilon=0.9、mu=5，522,139 个目标顶点、187,650,023 条投影边。该轮各一次：

| 实现 | 在线完整时间 |
|---|---:|
| 旧 HINSCAN 复现 | 122,105.369 ms |
| 改前 FLI，32 MiB 缓存 | 80,827.791 ms |
| 第一版自适应邻域缓存，不共享因子 | 209,515.912 ms |
| 第一版 BRI 首次查询 | 213,163.407 ms |

第一版的正确性仍通过，但性能回退严重。缓存缺失 7,810,597 次、淘汰 7,803,130 次，邻域重建读取 24,238,698,387 个倒排条目，仅生成邻域就耗时 154.224 s。原因是完整恢复右端邻域后很快被淘汰，相同因子的顶点还重复占用缓存。

这个结果反驳了“只把两端都缓存就能普遍加速”的假设，故没有直接把第一版作为本轮最终结论。失败日志和二进制仍保留，文件名为 `pscan_adaptive_unshared.exe`、`bri_adaptive_unshared.exe`。

Yelp 离线 BRI 构建 931.948 ms、大小 34,215,447 B。纯 FLI 构建 4,872 → 862 ms，新的文本读取、构建及保存总计 1,602.088 ms；旧流程纯同构图物化为 66,635 ms。首次建图部分改善，并不保证聚类访问策略也改善，两者必须分别验证。

仅共享因子但不复用因子对的中间版本也未达标：同一 FLI 在线 190,250.787 ms，邻域重建仍为 134.925 s，缺失 6,091,982 次。138,139 个不同因子行并不足以装入固定缓存；因此只压缩重复邻域并没有解决重复计算问题。该版本簇与角色通过，二进制 `pscan_shared_no_pair.exe` 保留。其随后重复的 BRI 冷查询被主动中止，不把未完成时间算作有效结果。

加上因子对区间表但没有流式缺失处理的版本仍为 182,726.599 ms。虽然复用命中 2,458,886 次，完整邻域生成仍耗时 133.254 s。这说明“缓存缺失时必须完整恢复”才是此时的关键问题，仅增加局部复用机制不足以解决。此版本簇与角色通过，二进制 `pscan_shared_pair_no_stream.exe` 保留，其重复 BRI 查询同样主动中止。`experiments/v11/final` 是这个未通过性能验收的中间实验目录，不是最终发布结果；后续验收数据放在 `experiments/v11/accepted`。

## 9. 最终验收：缓存压力下的精确流式回退

### 9.1 离线只保存 BRI 的完整在线时间

DBLP、Movies、IMDB 在最终代码上重新跑了 3 轮，以下取中位数；Yelp 使用同一会话已重新构图测得的旧基线，最终代码分别跑一次预建 FLI 和 BRI 首次查询，没有将失败版本的时间混入加速比。

| 数据集 / 参数 | 旧 HINSCAN 完整流程 | BRI 首次在线 | 加速比 | 离线 BRI 构建 | BRI 文件大小 |
|---|---:|---:|---:|---:|---:|
| DBLP A-P-A / 0.5,5 | 58.452 ms | 50.269 ms | 1.16× | 30.044 ms | 788,511 B |
| Movies A-M-D-M-A / 0.5,5 | 339.516 ms | 225.384 ms | 1.51× | 50.645 ms | 997,364 B |
| IMDB A-M-D-M-A / 0.5,5 | 7,768.768 ms | 3,589.813 ms | 2.16× | 226.027 ms | 7,982,439 B |
| Yelp U-R-B-R-U / 0.9,5（1次） | 122,105.369 ms | 65,889.086 ms | 1.85× | 931.948 ms | 34,215,447 B |

较小数据集的启动、调度抖动明显，例如 Movies 首次在线为 185.036–254.984 ms，DBLP 为 47.047–87.728 ms，不能把几毫秒差异解释成稳定的算法优势。IMDB 首次在线为 3,421.964–3,671.432 ms。Yelp 还需重复及多参数测试，本轮只证明该测试点的收益。MB 按十进制，MiB 按二进制；离线时间包含图读取、构建、保存及进程启动退出。

### 9.3 最终瓶颈与空间边界

IMDB 最终预建 FLI 查询第一轮：43,060 次缓存缺失、0 次淘汰、1,916,925 次邻域命中；因子分组得到 47,875 个记录。共享后工作集装得下，完全不触发流式回退。缓存缺失的倒排读取为 15,093,565 条；相同因子直接判断 46,439 次，因子对区间复用 178,720 次。pSCAN 精确判断入口调用数仍是 2,014,602。

Yelp 触发 5,684,341 次流式检查，扫描 5,002,312,940 个倒排条目。完整缓存行生成只读取 616,740,911 个条目，预建 FLI 测试中生成时间为 4.205 s；另有 17.735 s 的流式检查。它们均包含在查询时间内，不得重复加到总时间。相同因子直接判断 1,111,853 次，因子对区间复用 2,458,886 次；原 pSCAN 精确判断入口调用数仍是 10,359,646。

Yelp 首次查询的临时 FLI 为 879.805 ms；pSCAN 调用仍为 64.602 s，其中核心阶段 52.724 s。构造完整同构邻接表的开销已明显绕开，但在线候选枚举、证书访问和精确判定仍然主导总时间；没有消除投影规模相关的全部计算。

缓存额度未扩大：因子对区间表 1,572,864 B，邻域最多 31,981,568 B，合计 33,554,432 B（32 MiB）；目录、代表映射、工作位图、临时行及 pSCAN 状态另计。Yelp 在线证书表约 151 MB，因此不能说查询总内存只有 32 MiB。持久文件仅是 BRI；在线证书和临时 FLI 不写回索引。

### 9.4 验证与复现记录
