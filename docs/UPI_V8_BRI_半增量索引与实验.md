# UPI V8：BRI 基础关系与半增量元路径索引

## 1. 问题

旧 UPI 在最大长度内枚举 schema 上的非回溯半元路径，并为每条路径保存 FLI。该方案在小 schema 上可行，但路径数最坏随 schema 分支数和长度指数增长。辅助索引预算只限制 EQI、SCI 和 T-SECI，不能阻止基础 FLI 的组合爆炸。

UPI V8 将“支持任意元路径”和“为热点元路径提供毫秒级查询”分成两层。有限空间无法同时保证任意长度路径的首次查询都有数量级提升，因此系统采用精确的“离线基础索引+预构建热点+预算内增量晋升”。

## 2. 索引结构

### 2.1 BRI

BRI（Base Relation Index）将每种异构关系只保存一次，包含：

- 顶点类型名和数量；
- 关系类型的起点与终点类型；
- 去重、有序的正向和反向邻接表。

BRI 大小与 HIN 关系边数线性相关，不随元路径组合数增长。

### 2.2 有界离线热路径

UPI 保留现有 FLI/EQI/SCI/T-SECI 快速路径，但新增 `max-precomputed-paths` 硬上限，默认最多预构建 64 条半元路径。设置为 0 时得到纯 BRI 索引。枚举器达到上限立即停止，不再先生成全部组合后截断。

### 2.3 自适应缓存

未预构建路径首次查询时，系统从 BRI 精确组合半路径关系，在内存中建立临时 FLI，然后执行原 pSCAN 逻辑。该过程不保存投影图，也不返回近似结果。

`upi_promote_path` 可将一条昂贵或高频路径晋升为持久 FLI+T-SECI。晋升使用独立缓存目录，并接受必填的 MiB 级总预算。候选文件先写入 staging 目录，只有在总预算内才原子提交；预算不足时不留下部分索引。

## 3. 在线路由

1. 如果元路径属于离线 UPI 项，按 EQI -> T-SECI -> SCI -> FLI 路由。
2. 如果不属于离线项，先检查预算化自适应缓存中的 T-SECI/FLI。
3. 缓存也未命中时，加载 BRI，对任意合法对称元路径生成临时 FLI。
4. 所有路由最终均执行相同的 pSCAN 核心、联合和顶点角色语义。

新增的 BRI 回退也支持旧离线枚举器排除的回溯元路径。Movies `D-M-D-M-D` 已通过该路由精确执行。

## 4. 本机实验

### 4.1 Movies

| 阶段 | 索引大小 | 时间 |
|---|---:|---:|
| 仅 BRI，0条预构建路径 | 998,055 B | 离线构建 6 ms |
| `A-M-D-M-A` 首次按需查询 | 不增加持久索引 | 384 ms |
| 晋升该路径的 FLI+0.3 T-SECI | 新增 2,675,332 B | 498 ms |
| 晋升后 `epsilon=0.5, mu=5` | 总持久空间约 3.67 MB | 单次内部端到端 5 ms |

完整 Movies T-SECI UPI 为 12,497,956 B。只保留 BRI 和一条热路径时约 3.67 MB，空间减少约 70.6%。首次查询和晋升后查询的簇及角色文件都与精确基线一致。

1 MiB 缓存中尝试再晋升 `A-M-W-M-A` 被正确拒绝，FLI 和 T-SECI 都未部分提交。

### 4.2 IMDB

| 阶段 | 索引大小 | 时间 |
|---|---:|---:|
| 仅 BRI | 7,983,119 B | 离线构建 35 ms |
| 晋升 `A-M-D-M-A` 的 FLI+0.3 T-SECI | 缓存 40,100,592 B | 20.526 s |
| 晋升后 `epsilon=0.5, mu=5` | 总持久空间约 48.08 MB | 30次平均 49.81 ms |

完整 IMDB T-SECI UPI 为 77,363,298 B。混合方案只保留本次热路径时空间减少约 37.8%，在线时间与完整 UPI 的 50.27 ms 基本一致，相对旧 HINSCAN 的 7,918.48 ms 仍有约 159 倍加速。`epsilon=0.3/0.5/0.9` 的簇与角色全部与精确基线一致。

## 5. 当前边界和下一步

- 现在的晋升由显式工具触发，下一步可根据查询次数与首次耗时自动触发。
- 离线预构建目前以路径数为硬上限，还应增加包含 BRI、FLI 和辅助索引的全局字节预算和收益/空间排序。
- 首次未命中查询需要组合路径并执行 FLI pSCAN，不保证比 HINSCAN 快；系统的数量级加速目标针对离线热路径和已晋升路径。
