日期：2026-09-12。状态：候选设计与必要条件，不是完成的新算法，不是十倍加速证明。本轮不修改生产代码、不新增数据实验。

## 1. 从已知失败出发

包含森林结构实验 20260912-171914-containment-6h1pp2xv 已完整完成。
对于当前首关系证书，Yelp 的 U→R 无相同非空行/严格包含；IMDB movie→actor 的同类与可比对为 245,877，占对应投影边约 0.73%；Foursquare user→venue 为 9,532，约 0.036%。

这是带插桩、事后分组的机会诊断，不能换算成生产加速比，但足以阻止把相同前缀方案换名重做。

因此，新的候选须改变运算复用粒度，同时处理精确去重，不能仅寻找更多可包含的顶点对。

## 2. 候选筛选清单

本轮采用研究构思技能的失败边界、分解组合、简化检查；没有因算法名字新就假定有效。

| 候选 | 处理意见与理由 |
| --- | --- |
| 单父包含森林 | 不作为主方案；当前查询覆盖弱 |
| 保存全部严格包含对 | 不采用；空间可增大，Yelp 首关系结构问题仍存在 |
| 相同整行合并 | 已有因子等价缓存覆盖，不能当新贡献 |
| 共享见证前缀 | 已有负收益证据，不重复直接实现 |
| 挖掘全部频繁子集/最大双团 | 不采用全量索引；模式数量可能爆炸 |
| 原始关系的稀疏双团分解 | 保留为表示候选，但后续去重计数仍需解决 |
| 原始邻接的参考行+差分 | 暂缓；小输入差分沿后缀传播可扩大，不能直接得到小输出差分 |
| 概率相似度估计直接决定簇 | 不采用；不满足精确结果要求 |
| 保守摘要筛选+精确补算 | 可作辅助；不能先假设有大规模剪枝收益 |

| 每个目标顶点完整恢复位图再求交 | 已有工作，不能把它称为新的免物化结构 |
| 原始关系分区共享表示+按需集合运算 | 当前保留主候选；有精确递推，但总成本与批处理收益未证实 |

## 3. 候选的一句话解释

离线把原始关系的邻接集合表示成可共享的局部片段；在线对这些片段组成的并集/交集直接做精确计算，而不是先恢复每个顶点的完整元路径邻域。

这里“共享”指相同局部集合或相同局部运算状态的复用，不要求整行包含，也不要求两个目标顶点拥有相同见证前缀。

灵感来自因子化数据表示和共享布尔子图，但二者都不自动证明本问题的去重计数或十倍加速：
- [Olteanu 与 Schleich：Factorized Databases](https://databasetheory.org/sites/default/files/2017-01/p5-olteanu.pdf)
- [Bryant：Graph-Based Algorithms for Boolean Function Manipulation](https://www.cs.cmu.edu/~wklieber/15817-f08/ieeetc86.pdf)

这些基础思想已有研究，不声称“共享 DAG”本身是原创。潜在贡献必须是满足本项目约束的具体结构、执行规则和实测收益。

## 4. 离线只处理原始关系

对每个顶点类型建立固定的 ID 域划分，对每个原始关系方向保存邻接集合的压缩分区树。每个结点表示某个域内的精确子集合；相同类型、域和内容的子结构可共享。

只分裂非平凡部分，用压缩前缀跳过单支路径；原始非空行有 d 个元素时，未共享的紧凑二叉前缀树也只需 O(d) 个分支/叶结点。先有线性表示，再做精确共享；不能先枚举所有频繁子集。
等价验证不能仅比较哈希：须核对结点结构/终端内容。
空行不为每个关系复制整个顶点域映射；保存稀疏非空行入口及全局顶点信息。

在上述表示约束下，原始关系索引可保持 O(n+m+schema) 个机器字；具体常数仍需估算。若选用未压缩二叉树，应诚实计入其高度因子，不能仍声称线性。
它不含查询元路径、ε、μ、投影邻接表或相似度表。

重要限制：固定域划分只能共享落在相应区域中的局部内容；任意分散的共同子集未必能被紧凑捕获。重新排序顶点的成本与效果也没有得到证明，不添加让用户调分区数量的参数。

## 5. 在线精确运算核心

先讨论非独立模型的对称路径 P=H·H逆，记半路径见证集为 H(u)，倒排集合为 L(w)。闭邻域是集合表达式：

    E(u) = {u} ∪ union_{w in H(u)} L(w)

自元素始终显式计入，包括无半路径可达目标的孤立顶点。长路径仍可能需要在线生成半路径因子，耗时和工作内存必须计入；不能把 Yelp 的 U→B 当成已离线预知的关系。

对一个互不重叠的目标域分区 D = D0 ⊎ D1：

    count(E ∩ D) = count(E ∩ D0) + count(E ∩ D1)
    count(E ∩ F ∩ D) = count(E ∩ F ∩ D0) + count(E ∩ F ∩ D1)

在线递推同时限制所有并集操作数到当前域，然后应用：
- 空集合消去、重复精确结点合并；
- 与全集相交/相并的恒等式；
- 两侧相同表达式时，交集问题退化为一个集合计数；
- 不能简化则向两个不重叠子域递推；
- 最终到终端精确集合/单点后确定结果。

表达式未被完全化简到相同键，不代表集合不同；只表示不能通过该共享规则省略工作。
同一局部状态若被不同顶点或顶点对调用，可以复用其精确结果。键必须包含类型/域、操作种类、规范化操作数以及必要的查询层信息；不能只用端点 ID 或不核验的哈希。

这是递推的正确性，不是关于访问状态数量的效率证明。

### 为何不能直接把共享块大小相加

设原始集合 A={1,2,3}，B={2,3,4}，C={1,3,5}。

    |(A∪B) ∩ (A∪C)| = 3

若把四次两两交集计数直接相加，会得到 3+2+2+1=8，重复计数。
正确做法必须在同一个域里先执行幂等并集，再进行交集；不同域的结果才可相加。
例如域分成 {1,2} 与 {3,4,5}，两个域内公共元素数分别为 2 和 1，合计 3。

例子中的集合仅用于说明运算，不是建议把在线 E(u) 预存到离线索引。

## 6. 度数、相似度与输出语义

用精确集合计数得到 du=|E(u)|；用交集计数得到 Cuv。
已确认相邻的顶点对，按原结构相似度条件比较 Cuv² 与 ε² du dv。
“公共邻域有交集”不等于顶点本身相邻；候选的元路径邻接条件不能删掉。

允许用严格下界/上界提前判定，但不改变 ε 或引入概率错误。所有未判定情况继续精确处理。
核心的 μ 仍计入自身；核心连通、非核心多簇归属、未归属点的 hub/outlier 判定必须完成。
原始 pSCAN 的语义和剪枝条件保留；局部共享只改变所需集合运算的执行方式。

对一般非对称闭合路径，集合运算原语可以使用，但上面的半路径公式不直接成立；问题对应的邻接/聚类处理仍须另行完成。不能据此宣称已经覆盖全部合法输入。

## 7. 不形成另一种全图物化

禁止提前为所有 E(u) 编译并保存完整结果树，再把这称作免物化。
只保留原始关系的离线结点、查询所需半路径因子，以及按需访问的运算状态和结果摘要。
单次计数可以只返回整数/严格区间，无须生成完整邻居列表。

但是，所有局部状态无限记忆化仍可能隐式存下庞大的查询结果。离线线性不能推导出在线工作空间线性。
如果采取有界保留，必须核算键、操作数和活跃栈的真实内存；淘汰不影响精确性，但可能破坏期望的复用时间界。
目前还没有给出同时保证小工作空间和高复用的完整调度方案，这是待解决项，不把它藏成新的用户缓存参数。

## 8. 仅加速求交，仍可能达不到目标

设同口径旧 HINSCAN 完整纯计算时间为 TH，新流程无法被本模块减少的部分为 F，其余可加速工作原时间为 C，模块加速 r 倍，新增准备为 A：

    Tnew = F + A + C/r
    十倍目标要求 F + A + C/r <= TH/10

只要 F+A 已超过 TH/10，无论交集模块多快都达不到目标。
这里 F 包括尚未被替代的候选生成、状态处理、核心连接和完整角色工作。不得把不同时期、不同插桩口径的阶段时间拼起来求 r。

因此当前候选若只替换相似度内核，最多是一个待验证的组成部分，不能直接当作目标算法交付。

## 9. 批量候选判断的充分条件

为了跨过上一节的限制，还需减少逐对调度。下面给出正确但尚未证明便宜的批量判据。

对候选顶点组 G，先确认 G 全部属于 u 的元路径邻居。设：

    JG = intersection_{v in G} E(v)
    KG = union_{v in G} E(v)
    dmin = min_{v in G} |E(v)|
    dmax = max_{v in G} |E(v)|
    L = |E(u) ∩ JG|
    U = |E(u) ∩ KG|

则对所有 v∈G：
- 若 L² >= ε² du dmax，可全部判相似；
- 若 U² < ε² du dmin，可全部判不相似；
- 否则须细分组或逐对精确处理。

也可用不超过 L 的已证明下界、以及不小于 U 的已证明上界，仍然安全。
批量给 u 增加相似邻居计数时须使用尚未计入的不同顶点数，排除重复组覆盖，并正确处理自身。
批量连接仅适用于已确定核心的相似边，不能因为组内有一个核心就合并整组。

真正难点：任意组的 JG 往往很小、KG 很大，证书可能很松；构造它们也可能比逐对检查更贵。
本轮没有证明这项批处理会有效。旧共享前缀实验的负收益正是必须警惕的证据。

## 11. 继续推导：具体结点与运算状态

以下是可实现的表示约束，不是已实现的数据结构。

### 11.1 离线结点

每种目标类型的局部 ID 域使用固定二分规则，不让用户选择分区数量。
非空行入口为 `(relation_direction, source_vertex, root_handle)`，不对所有关系复制所有空行。
结点有三类：单点、完整域、压缩分支。分支记录域/前缀、两个孩子及精确基数；压缩边隐含跳过的空域。空集用专用句柄。
结点的语义始终是某一类型、某一 ID 域中的原始邻接子集。共享前必须核对完整结构；不同类型或不同域不能仅因孩子编号相同就合并。

一个 d 元素行可以从至多 d 个单点叶和 d−1 个二叉分支开始，再合并完整域及重复结点。因此全部非空原始行在双向存储后仍为 O(m) 结点上界，入口和类型/schema 信息另计。
这是机器字数量的界，不是“和输入文本一样大”的承诺。孩子句柄、域描述、基数、入口以及驻留去重表均有常数成本；构建工作内存也不等于落盘索引大小。

### 11.2 在线表达式与精确递推

对给定关系序列 Q=(r1,...,rl)，定义端点集合：

    Reach(v, empty) = {v}
    Reach(v, ri...rl) = UNION_{w in row(ri,v)} Reach(w, r(i+1)...rl)

该式描述按关系序列的可达端点，不枚举路径实例；它本身也不规定非对称投影应如何聚类。完整输入语义仍必须遵守 HINSCAN 的合法元路径定义。
半路径因子只是对适用的对称查询进行的一种重写，并不是把其他合法输入排除出去的依据。

在线句柄可指向原始行、单点、惰性 Reach 状态或规范化 OR 操作。Reach 状态必须带查询后缀/层号，含重复类型的路径也不能把不同层混为一谈。
OR 只做安全的幂等化简；相同句柄重复出现可删除，两个不同句柄不能仅凭基数相同视为相等。

精确计数在互斥 ID 域上递归：

    Count(X,D):
        在 D 上限制并简化 X
        EMPTY -> 0; FULL -> |D|; 原始精确结点 -> 已存基数
        无法直接确定 -> Count(X,D0) + Count(X,D1)

    Common(X,Y,D):
        在 D 上限制并简化 X,Y
        任一 EMPTY -> 0
        一侧 FULL -> Count(另一侧,D)
        两侧相同表达式 -> Count(X,D)
        无法直接确定 -> Common(X,Y,D0) + Common(X,Y,D1)

限制到单点后，Reach 可用分层布尔可达递推精确判真伪，所以存在有限的精确终止方式。但沿单点逐个处理可能非常慢，不能把“可终止”当成高效。
所有 OR 的计数都必须先消除目标重复；不能将孩子的基数相加，除非已证明孩子所在目标域互斥。

### 11.3 不能把一个状态当成一次常数运算

设一次查询实际访问的状态序列为 V（淘汰后重算要重复计入），状态 s 的操作数个数为 k_s。另设 A 为展开原始关系和定位压缩子树的总工作，Z 为规范化、键比较和查找的总工作。

    T_set = O(A + sum_{s in V}(1+k_s) + Z)

若逐状态排序规范化，排序部分可达 sum O(k_s log(k_s+1))；不能仅给出 O(不同状态数)。
缓存内存必须包含全部操作数键，而不仅是一个计数值：

    M_query = 因子/可达中间状态 + 活跃递归栈与操作数
              + sum_{保留状态 s} O(1+k_s) + 聚类输出及状态

逐顶点计数后清除局部缓存可以避免永久积累所有根的结果，但会失去跨顶点复用；无限保留则没有小空间保证。当前尚未给出兼得的调度证明。

## 12. 关键反例：共同部分不能无损穿过路径后缀

设 F_Q(S) 是集合 S 沿固定后缀 Q 能到达的所有端点。对任意一组集合 A_i：

    F_Q(UNION_i A_i) = UNION_i F_Q(A_i)
    F_Q(INTERSECTION_i A_i) SUBSET_OF INTERSECTION_i F_Q(A_i)

第一式由可达的存在量词直接得到。第二式只有包含关系：所有行共有的同一个中间点当然产生共同端点，但不同的中间点也可能各自走到同一个端点。

手算反例：有 k 个用户 ui，各有一个不同的评论 ri，所有 ri 都属于同一个商家 b；查询为 U-R-B-R-U。

    ui -- ri -- b,  i=1,...,k

各用户第一跳邻居集合 {ri} 两两不交；但所有用户沿完整查询的闭邻域都是全部 k 个用户。
因此真实度数是 k，任意不同用户的结构相似度是 k/sqrt(k*k)=1。
把第一跳交集传播到后缀得到空集，遗漏了这 k 个真实共同端点。即使补上相邻点的通用闭邻域下界 2，对 k 很大的情况也仍很松。

问题对应的量词差异是：

    所有用户共用一个中间见证：存在 w，使每个用户都经 w 到达
    所有用户到达同一终点：对每个用户，各自存在一个可用见证

后者并不要求各用户的见证相同。
这不是说共享 DAG 处理不了这个例子：ri→b 的后续表达式相同，按需化简有可能很快识别它。反例只否定“原始共同邻居摘要可以无损直接传播”的捷径，不能据此断言所有索引方法无效。

该反例与 Yelp 的 U→R 首关系结构相容，但这里是理论构造，不是声称真实 Yelp 的用户都属于同一个商家。

## 13. 批量规则的代价门槛，而非再命名一个证书

第 9 节的规则是充分条件，正确性成立；它不附带廉价构造算法。
如果为一个组 G 现算每个 E(v)，再求 JG/KG，那么第一次至少需要访问这些组成员，并可能重新完成原先试图跳过的邻域工作。
若一个证书仅用于一个外部顶点 u，必须比较完整建证书成本与这批实际避免的逐对工作，不能只报告批量判定本身的时间。

更一般地，设可复用证书构造成本为 B，服务 q 次实际请求，每次检查成本 h，实际避免的原精确工作之和为 W，则至少需要：

    B + q*h < W

这里 W 只能计入原 pSCAN 本来会做、且确实被替代的工作；不能把被其他剪枝免掉的顶点对算作收益。q 也必须来自可执行调度，不能来自事后观察未来调用。
批量更新核心计数仍要处理组重叠、未计数成员和核心连接；这些费用尚未包含在上式中，必须另外核算。

两种看似直接的补救都不能直接采用：

1. 离线为所有后缀保存精确 JG/KG：后缀未知且数量可能增长，重新引入原先禁止的按路径结果积累。
2. 在线为所有顶点恢复完整闭邻域的分块成员表，再建立倒排：这仍然恢复了完整查询投影关系，只是按块编码，不能因为未写邻接表就称为免物化。

原始关系中已有的 FULL 子域、相同表达式以及小差分可以提供局部便宜判据；但若只在逐对求交内部使用，其收益仍受第 8 节的端到端时间下限约束。

## 14. 本次推导的判定

已经明确的部分：原始关系分区索引可给出线性机器字存储上界；不重复计数的惰性集合运算可精确定义；组级相似度充分条件是正确的。

没有通过的关键部分：尚无一个可执行分组与状态保留规则，能在不恢复所有闭邻域的前提下，以足够小的构造代价同时减少候选枚举和精确求交。原始共同部分沿后缀传播不能填补这个缺口。

因此本候选暂时只能定位为“有正确性基础的集合计算内核”，还不能定位为满足十倍目标的新索引主算法。本次不进入生产实现或三数据集实验；也不将上述反例扩大成任何算法都不可能十倍加速的结论。

后续设计必须先给出具体操作：输入某个原始索引结点和查询后缀，直接得到一批尚未重复计数的候选及有效界；明确它避免了哪些访问、其自身访问量和保留量是多少。仅给出另一条正确不等式或笼统说“复用共享部分”，不算通过这一门槛。
