# UPI 时间效率实验（2026-09-02）

## 1. 对比口径

旧流程计时包含：读取 HIN、按元路径物化同构图、写二进制图、运行原版 pSCAN、写簇结果。

UPI 计时包含：启动查询程序、读取 manifest、加载选中的 EQI/SCI/FLI、运行保持相同语义的 pSCAN、写簇与顶点角色结果。离线索引构建时间不计入在线时间，单独报告。

程序均为同一台机器上的 Release 构建。DBLP、Movies、IMDB 的新算法分别重复 30、30、20 次；旧流程因代价较高分别重复 5、5、3 次。DBLP 稠密路径和 Yelp 各只完成一次旧流程，相关加速比视为初步值。

## 6. Yelp 边界分析与 SECI 实验

Yelp 的旧完整流程由两部分组成：

- HIN 读取、物化及写图：79,421.72 ms；
- 原版 pSCAN 读取物化图、聚类及输出：48,200.98 ms。

原 FLI 端到端为91,202.39 ms，只获得1.40倍加速。原因不是实现常数，而是该路径同时不满足原有两种快速结构：

- 187,650,023条投影边使逐边 SCI 很大；当前内存构建方式预计需要数GB峰值内存。
- 522,139个顶点虽能归并为138,139个邻域等价类，但代表邻域仍有182,466,215个条目，EQI 不能获得数量级压缩。

全量 SCI 成本探针均匀抽样了1,000,000条真实投影边。结果显示全量公共邻居证书预计需要约1,860秒计算；位打包文件仍需1.24--1.27 GB，当前内存构建器核心数据约3.76 GB。因此不能简单把 Yelp 改走全量 SCI。

在此基础上实现了 SECI（Selective Equivalence Certificate Index）原型：先按完全相同的闭邻域归并顶点，再对等价类商图使用度数上界剪枝，只保留相似度不低于覆盖下界0.9的精确类间证书。覆盖下界是离线索引策略，不是本次查询参数；同一索引可精确回答任意 `epsilon >= 0.9`，更低 epsilon 需要回退 FLI 或由另一个覆盖层处理。

| SECI 指标 | Yelp `U-R-B-R-U` |
|---|---:|
| 顶点 / 投影边 | 522,139 / 187,650,023 |
| 闭邻域等价类 | 138,139 |
| 商图边 | 47,116,186 |
| 通过0.9度数上界的类边 | 7,797,158 |
| 最终保留的类证书 | 905,765 |
| 这些类证书代表的跨类相似顶点边 | 17,124,722 |
| 类内隐式相似顶点边 | 41,375,848 |
| 离线 SECI 构建时间（读取现成物化图） | 30.474 s |
| SECI 文件 | 14,062,936 B |
| 20次在线端到端平均 / 中位数 | 231.67 / 228.82 ms |
| 相对旧 HINSCAN 完整流程 | 550.89x |
| 相对原 FLI 在线查询 | 393.67x |
| 相对原 pSCAN 已物化图阶段 | 208.06x |

`epsilon=0.9, mu=5` 时，SECI 的簇结果文件与原 pSCAN 的 SHA-256 完全相同，角色文件与原 FLI 精确算法也完全相同。使用同一份0.9覆盖索引查询 `epsilon=0.95, mu=5`，簇结果仍与原 pSCAN 的 SHA-256 完全相同，证明索引不是只对构建边界值写死。

本轮为了快速复用已有1.5 GB基线图，原型构建器直接读取物化图；因此30.474秒不是从原始HIN开始的完整离线时间。若机械加上本轮已有的79.422秒物化阶段，当前实验型离线总计约109.896秒。正式实现应从 FLI/UPI 流式生成代表邻域和类边，不把物化图作为持久索引文件。

## 7. 结论

当前 UPI 已在普通、中型和高重复稠密路径上分别取得约4--66倍和约669倍以上的端到端加速，且结果保持精确。随着投影规模从35万边增长到655万边，SCI 的加速由约21倍增长到约66倍，说明把结构相似度计算移到离线阶段确实是有效方向。

Yelp 的 SECI 实验进一步表明，第四种结构不必是全量外存 SCI。将“闭邻域等价类的隐式完整二部关系”和“高相似类边的选择性证书”组合后，可以把1.8765亿条投影边压缩为90.6万条在线类边，在结果精确的前提下把旧完整流程从127.6秒降到约0.232秒。当前结果已达到约2.74个数量级的端到端提升；下一步重点是把 SECI 接入 UPI 的免持久物化构建与自动路由，并通过多覆盖层支持更宽的 epsilon 范围。

## 8. SECI 小规模补充实验

服务器不可用期间，在本机对 DBLP `A-P-A`、Movies `A-M-D-M-A` 和 IMDB `A-M-D-M-A` 构建了覆盖下界0.5的 SECI。每组在线查询重复30次，统计完整进程与输出时间。

| 数据集 | SECI构建 | SECI大小 | 在线平均 | 在线中位数 | 旧完整流程 | 加速 |
|---|---:|---:|---:|---:|---:|---:|
| DBLP | 7 ms | 311,784 B | 19.14 ms | 17.97 ms | 89.91 ms | 4.70x |
| Movies | 259 ms | 621,620 B | 16.05 ms | 15.66 ms | 348.86 ms | 21.74x |
| IMDB | 10.553 s | 8,559,584 B | 84.26 ms | 84.02 ms | 7,918.48 ms | 93.97x |

三组数据的簇和角色共6个输出文件全部与基线哈希一致。IMDB 还构建了0.3覆盖层，一份索引精确通过了 `(0.3,2)`、`(0.5,5)`、`(0.7,5)` 和 `(0.9,2)` 四组簇结果校验；代价是索引从0.5层的8.56 MB增长到34.38 MB。这验证了 SECI 的覆盖范围—空间—加载时间权衡，也是后续多层自动路由的直接实验依据。

后续将 SECI 接入完整 UPI 并升级为连续存储v2后，IMDB `A-M-D-M-A` 的30次端到端平均进一步降至52.74毫秒、中位数51.08毫秒，相对旧完整流程提升150.15倍。v2文件大小仍为8,559,584字节，内部索引加载由约42毫秒降至约4毫秒。Movies v2端到端平均15.12毫秒，对应23.08倍加速。
