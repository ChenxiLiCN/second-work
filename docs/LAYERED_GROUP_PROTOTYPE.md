# 多数覆盖组与分层完成：独立原型验证

日期：2026-09-13。

## 结论与边界

已实现可重复运行的独立 Python 原型：离线原始关系覆盖组、在线分层证书规划、测试侧完整结果合并。新原型 18 项测试、旧模型 14 项测试，共 32 项通过；16 个固定微型探针的完整结果均与独立语义参考一致。

这是机制与有限范围正确性验证，不是生产 C++ 实现，不是服务器时间实验，也没有证明十倍加速。残余部分由测试中的独立精确参考求解，尚未接入 C++ PSCAN；不能把参考求解器称为 PSCAN。未修改现有 C++、服务器脚本或数据集。

## 已实现流程

### 离线：只用原始图与 schema

每种原始关系的两个方向分别保存：原始邻接行、严格多数覆盖组、原始两跳闭度数标量。构造接口没有元路径、ε 或 μ。

将关系终点类型的编号域补成二次幂大小，在二进制区间 Z 上收集满足 `2*邻居落在Z内的数量 > Z的长度` 的源顶点。只保留非空组。组内任意两行必有共同原始邻居，因此组是该关系两跳投影中的完全子图；不用保存其内部顶点对。

例：四个源点分别连接四个中间点中的三个。每行覆盖整个四点区间的一半以上，离线只记录一个包含四个源点的组，即可证明六条两跳关系，不存这六条展开边。叶子组对应原始倒排表；非叶子多数组才提供不同于单个见证的覆盖信息。

构建时，只沿每条实际邻接的区间祖先累计计数，不扫描所有“源点×区间”。原始边先去重。精确两跳闭度数属于已有索引思路的标量元数据，本原型仅复现它，不把它当作新贡献；其构建一次生成一个临时去重集合，保留度数后释放，不保留各行两跳邻接。

### 在线：先证明，后决定是否需要构建因子

对于 `P=Q R R逆 Q逆`：

1. 建立半路径的分层视图。相同类型在不同路径位置是不同状态；先去掉不在完整半路径上的状态，再通过原始关系连接确定精确投影连通分量。不展开投影边。
2. 分量大小小于 μ，直接判为全 outlier。若一个覆盖组覆盖该分量全部有效倒数第二层顶点，则整个分量是完全图；满足 μ 后直接输出一个全核心簇。
3. 对尚未完成的分量计算安全界：完整闭邻域大小的上界、前缀可达数量上界、组成员对应目标数的下界。长路径使用截断路径计数及最大值传播，不能把重复见证当作不同邻居相加。
4. 一个组对应目标数的下界为 L，其目标闭度数最大值的上界为 M。只有 `L>=μ` 且 `L>=ε*M` 才接受：组内任意两点闭邻域交集至少 L，结构相似度至少 L/M。使用整数和有理数比较，不做浮点近似接受。
5. 在前缀分层图中批量连接已接受组，排除不可达组成员。不会逐组展开其对应的全部目标列表，也不保存相似边表。
6. 只有整个原始投影分量的目标都已证明为核心，且证书连接为一个簇，才直接完成。其他分量整体保留，不只删其中几个点。

整分量保留很重要：不同投影分量之间无元路径邻接，因而独立处理不会损失边界归属或 hub 所依赖的邻居簇信息。测试合并器在残余分量中运行独立参考，再把局部簇编号映射回原始目标 ID；已经完成的核心簇以最小原始核心 ID 命名。

## 索引与计算成本

对一行 d 个不同原始邻居，严格多数组成员记录至多 `max(0,2*d-1)` 条：最多 d 个叶子和 d−1 个两侧均有实际叶子的分支祖先。对一个方向求和即可得到线性成员界。一个有 m 条不同原始边的关系，两个方向的组成员合计不超过 4m；非空组头数量也不超过成员记录数量。原始双向邻接、度数数组、类型域及关系头另计。

原型还保留规范化原始边列表供独立测试参考读取，这也是原始边的常数倍副本，不是展开图。Python 对象体积、最终二进制索引字节数均未测量；不能用成员条数直接当作文件大小比例。

离线多数计数工作约为每条原始边访问终点树的祖先，另有去重和排序。两跳度数构建的倒排访问可能很大，例如一个高频中间点会导致大量重复访问。因此不能把“新增组成员线性”说成“整个离线构建也是线性时间”。探针单独报告祖先访问和度数倒排访问。

在线若 M 为按路径位置累计的原始关系条目数、V 为分层顶点数、H 为相关覆盖组成员条数，则证书部分采用固定次数的分层扫描和并查集。当前 Python 实现还有分量排序，保守计为 `O((M+V+H)*α(V+H)+V*log(V+1))`，按哈希访问和字长整数模型理解。ε 的超长有理数字符串涉及大整数成本，不能无条件视为常数。

若仍有未完成分量，当前标量传播会扫描整条查询路径对应的关系，不只扫描残余分量。完成部分分量不代表这些扫描已经被消除。当前原型没有把这个成本隐去，也未实现额外剪裁优化。

生产完整在线时间必须为：分层判断 + 标量/证书计算 + 残余因子构建 + PSCAN + 结果合并。读索引和写结果排除；内存分配、复制、映射必须包含。离线计时排除读原图和写索引，包含实际索引结构及元数据构建。

## 实测微型机制结果

下面是固定探针中的 48 目标点案例。原始条目读取与组成员访问是不同工作，不能相除得到加速比；这里也没有计入残余精确求解器的工作、全部标量访问、排序、分配等 CPU 操作。

| 结构及参数 | 投影无向边 | 直接完成目标 | 残余目标 | 规划器原始条目读取 | 组成员访问 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 四中间点、每点连三个，ε=1、μ=48 | 1,128 | 48 | 0 | 432 | 240 |
| 三中间点、每点连两个，ε=0.5、μ=2 | 1,128 | 48 | 0 | 288 | 416 |
| 同上，ε=1、μ=48 | 1,128 | 0 | 48 | 288 | 224 |
| 匹配图，ε=0.5、μ=2 | 24 | 48 | 0 | 144 | 48 |
| 环图，ε=0.5、μ=2 | 48 | 48 | 0 | 288 | 432 |

前两行证明两种完成机制确实执行：第一行由覆盖组提前完成，第二行由多个相似度证书连接完成。第三行是真正的限制：三点域补成四点后，每行覆盖两个点不满足根区间严格多数；高 ε 下较小组也不足以证明全分量相似，虽然真实投影仍是完全图，原型必须回退。

匹配图和环图在这些参数下也能直接完成，但原图本来很稀疏，所以不能据此推断比 PSCAN 快。另一个带边界点和 hub 的 14 点案例只直接处理 1 个孤立点，保留另外 13 个目标；说明复杂混合分量仍可能几乎全部回退。

四中间点的 48 点案例有 144 条原始边，两个方向合计 524 个组成员记录、102 个组头和 52 个度数标量；祖先计数访问 1,440 次，度数倒排访问 5,616 次。后者提醒我们离线标量构建也有独立代价。这些仍然是条数，不是索引字节数或耗时。

## 正确性与输出验证

- 穷举 4×3 的全部 4,096 种关系图，双向检查每个组的精确成员、内部共同邻居、成员上界和两跳闭度数。
- 600 个随机链式 schema 图，各三组参数，共 1,800 组查询，完整路径长度为 2、4、6、8 条边。
- 150 个带环三类型 schema 图，各三条重复类型路径，共 450 组查询。
- 既有八个语义用例；孤立和空类型；反向目标类型；重复边；μ、ε 边界；原始 ID 重排；同一离线索引的多次不同查询与指纹不变。
- 明确检查不可达组成员与不完整半路径不能造成虚假合并；检查短、长路径上相似度证书确实被接受并完成结果，而非全靠回退。
- 检查全核心已完成分量与含 border/hub 的残余分量共同合并，输出原始 ID、核心集合、全部簇归属和角色均匹配。
- 16 个固定微型探针全部匹配；命令行 JSON 可解析，统计明细之和等于汇总。

测试先于实现运行，最初失败于模块不存在。输出检查又复现了 dataclasses.asdict 把 Counter 项变成元组键的问题；新增失败回归测试后改为普通字典序列化，重新通过全部测试。该修复不涉及聚类逻辑。

独立审查已对分层裁剪和界的保守性给出阶段性未发现缺陷的反馈，但审查会话随后中止，没有完整最终审查结论。本记录不把阶段性反馈冒充最终审查通过；C++ 接入前仍应完成审查。

## 覆盖范围与下一步

模型只支持 A-Z 类型名、不同类型之间每对至多一种无标签原始关系及其隐式逆关系、正偶数边的对称类型路径；非法或模型不支持的输入明确拒绝。这只是隔离验证器的范围，不是缩小正式问题定义。正式实现对模型之外的原有合法输入必须保留原处理路径，尤其不能仅凭类型对称就接受有向同类型关系。

下一步是独立 C++ 接入与微型差分核对，不是直接启动三数据集整套测试：

1. 完成审查，将组结构接入原始关系离线索引格式，兼容原索引加载路径。
2. 在 FactorIndex 构建前调用分层完成器；让因子构造只接收残余目标，而非先构建全部因子再删除。
3. 保持 PSCAN 聚类内部逻辑不变，验证残余源 ID 映射与完整角色合并。
4. 微型 C++ 全结果核对通过后，再给服务器脚本：Yelp、IMDB large、Foursquare 每组一次，分别报告 HINSCAN 完整计算、离线构建、索引在线纯计算及实际索引字节数。

主要风险仍是证书覆盖率：大混合分量或过松的长路径上界可能让全部分量回退，增加的证明开销反而拖慢在线。索引线性成员界与十倍性能目标是两件事；前者不能证明后者。
