# V13：见证交集界与按需激活试验

日期：2026-09-07。研究入口为 `bri_query_adaptive_bounds`；默认 `bri_query_index` 仍是 V11，`bri_query_blocks` 保留 V12。没有修改聚类输入参数、核心定义、核心连通性或非核心多簇归属规则。

结论：Yelp 首次在线三轮中位数由 V12 的 42.95 s 降为 23.85 s，约快 1.80 倍，相对本轮 HINSCAN 完整复现为 5.15 倍。Movies、IMDB 基本持平。结果正确，持久索引未增大；尚未实现普遍的数量级提升。

## 1. 本轮要解决的工作

V12 已能跳过已证核心块内的候选，但跨块仍存在大量相似度谓词请求。V13 尝试复用更细粒度的见证倒排交集，避免每个候选都重新求完整邻域交集。它与 V12 共用同一份与元路径无关的持久 BRI。

离线输入只有图及 schema。在线从元路径生成临时 FLI，执行 V12 块证明与候选跳过，再按下列策略做剩余精确判定。所有新增计算都计入在线；没有保存完整投影图、全量元路径索引或查询历史。

## 2. 精确界及正确性边界

令当前闭邻域为 N[u]，候选 v 的见证集合为 W(v)，见证倒排为 S(w)。非空 W(v) 满足：

`N[v] = union(S(w), w in W(v))`。

对固定 u 按需计算 `c(u,w) = |N[u] intersect S(w)|`，同一次 u 激活期间复用该计数。于是：

`max c(u,w) <= |N[u] intersect N[v]| <= min(d(u), d(v), sum c(u,w))`。

- 下界达到当前精确整数相似度阈值，直接判相似。
- 上界小于该阈值，直接判不相似。
- 其余情况仍走原有列表、位图或流式精确检查。
- 多个见证倒排可能重叠，因此**求和只能作为上界**，不能拿来证明达到核心密度。
- 无见证的孤立点仍走原有精确处理，不把空集的最大值当成证据。
- 计数只对当前完整邻域有效；切换到不同规范化邻域时用 epoch 失效，回绕时清空标签。相同见证列表的规范化顶点拥有相同闭邻域，才允许复用。

## 3. 代价控制与按需激活

第一版对所有未被旧缓存解决的谓词都应用该界，IMDB 单轮从 2.92 s 退化至 3.82 s：虽提前接受/拒绝了约 79 万次请求，却新增约 3.97 亿次倒排访问。在 Yelp 上同策略从 43.04 s 降至 25.59 s。不能根据 Yelp 的成功一律启用。

第二个探索版本仅在缓存有压力且右端邻域未缓存时启用，Yelp 为 33.58 s（对照 44.18 s），但限制过强。该二进制保存为 `experiments/v13/bri_query_pressure_misses_pilot.exe`。

最终试验版本采用：

1. 无缓存压力时保留原来的邻域交集路径。
2. 有压力时，除已有等价行和因子对缓存命中外，使用见证交集界；右端即使已缓存也可以使用该界。
3. 将完整左邻域激活从“候选生成后立即执行”推迟到“确实需要底层精确谓词”时。已有边证书、块连通性等已解决的候选不触发激活。

压力判据复用 V11 现有规则：邻域缓存预算为 0，或发生至少 1024 次驱逐且 misses > hits/4。它是内部执行启发式，不是新聚类参数，不影响结果正确性，也没有普遍的速度保证。默认邻域/因子对缓存总预算依旧为 32 MiB。

## 4. 计时口径与数据

最终串行测量如下。在线版本为三轮中位数；HINSCAN 每组重新测一次，不能当作三轮统计。

| 数据集 | HINSCAN 完整复现（1 次） | V12 在线（3 次中位数） | V13 在线（3 次中位数） | V12 / V13 | HINSCAN / V13 |
|---|---:|---:|---:|---:|---:|
| Movies | 343.739 ms | 155.147 ms | 151.892 ms | 1.02× | 2.26× |
| IMDB | 7,897.388 ms | 2,887.626 ms | 2,869.212 ms | 1.01× | 2.75× |
| Yelp | 122,828.331 ms | 42,951.437 ms | 23,852.076 ms | 1.80× | 5.15× |

Yelp V13 三轮为 23,852.076 / 24,025.391 / 23,730.893 ms，V12 三轮为 43,494.596 / 42,487.145 / 42,951.437 ms。Movies、IMDB 的时间区间重叠，不将约 1–2% 的差异解释为已证实提速。两组的最终新界检查数均为 0，执行保护起到了避免无条件新界开销的作用，但仍不能承诺其他查询不退化。

实验命令如下：

```powershell
experiments/benchmark_v13.ps1 -Datasets movies,imdb_legacy,yelp -Modes v12,adaptive -Repeats 3 -IncludeHinBaseline -RunName final
```

- V12 为修改前保存的独立二进制；V13 为最终 `bri_query_adaptive_bounds`。
- 每个在线版本独立进程执行三次，报告中位数。偶数轮反转版本顺序；操作系统文件缓存未清空。
- 每组数据另重新执行一次 HINSCAN 完整复现：从 HIN 文本完整构图＋未修改的上游 pSCAN，不是官方 HINSCAN 源码。
- 在线时间包含进程启动、BRI 加载、临时 FLI 构建、查询、簇及角色输出、进程退出。
- Movies、IMDB 使用 A-M-D-M-A、ε=0.5、μ=5；Yelp 使用 U-R-B-R-U、ε=0.9、μ=5。
- Yelp 使用已有规范化输入 `data/derived/normalized/yelp`，与 V12 同口径；没有修改原始数据。

## 5. 正确性验证

`verify_adaptive_fli` 直接从 HIN 全路径集合遍历建立闭邻域，并用独立整数相似度公式及直接聚类作为 oracle。13 个图、两种路径、五个缓存预算、五个 ε、四个 μ；包括无点图、孤立点、完全图、随机图、跨块桥接、重复见证和重叠块。

最终通过 71,845,920 次邻域交集谓词对照、18,200 组聚类对照。覆盖新界接受、拒绝、复用及两种邻域后端下的延迟激活。18 组真实参数查询的 36 个簇/角色文件与已有 V11 精确参考 SHA-256 一致。主时间试验另外比较 V12 与 V13 的簇/角色文件，并比较上游 pSCAN 簇文件。

```powershell
build-cmake/bin/verify_adaptive_fli.exe experiments/v13/fixtures
experiments/validate_v13.ps1
```

原始正确性记录：`experiments/v13/correctness-final.log`、`experiments/v13/real-correctness-adaptive.csv`。

## 6. 空间与计数口径

离线索引格式未变，实验逐数据检查 BRI 的 SHA-256 没有变化。V12 测得的 BRI 构建时间为 Movies 31.206 ms、IMDB 207.843 ms、Yelp 751.416 ms；这是上一轮三次中位数，**不是本轮重新测量**。文件大小仍为 997,364 / 7,982,439 / 34,215,447 B。

新增工作区为每个见证点一个 uint64 计数与 uint32 epoch，约 `12 × 见证点数` 字节，查询结束释放；不会随处理过的元路径数量增长。此工作区计入 `adaptive_workspace_bytes`，不属于 32 MiB 邻域缓存额度；边证书表、临时 FLI 等也不属于该额度，因此不能把 32 MiB 当成总内存峰值。

本轮路径的见证类型分别为 D / D / B，对应额外计数工作区 Movies 28,680 B、IMDB 220,200 B、Yelp 192,000 B。Yelp 边证书表仍为 150,994,944 B，没有因为完整交集调用减少就缩小。

`exact_similarity_checks` 仍是调用底层判定器的请求数，包含等价行命中、因子对界命中和新增见证界判定，不能再把它误读为完整邻域交集次数。新增 `adaptive_full_checks` 是列表、位图及流式路径调用数之和；其中仍可能提前终止。`witness_entries_read` 是计算见证交集界时的额外原始倒排访问数，必须单独报告，不能因为完整交集调用下降就声称总访问次数同比下降。

### Yelp 工作量变化

| 指标 | V12 | V13 |
|---|---:|---:|
| 底层判定请求 | 8,600,802 | 8,600,802 |
| 等价行直接判定 | 12,024 | 12,024 |
| 因子对缓存命中 | 1,866,791 | 1,866,791 |
| 列表/位图/流式交集路径调用 | 6,721,987 | 68,297 |
| 新见证界接受 | 0 | 35,034 |
| 新见证界拒绝 | 0 | 6,618,656 |
| 为生成邻域读取倒排条目 | 815,883,126 | 202,381,701 |
| 流式路径读取倒排条目 | 4,949,290,816 | 108,518,017 |
| 新见证界额外读取倒排条目 | 0 | 4,348,724,699 |

保存的 V12 二进制没有输出 `adaptive_full_checks`，该列按其判定请求减去等价行及因子对命中推导（该版本只有这三条分支）。V13 直接输出该计数；核对 8,600,802 = 12,024 + 1,866,791 + 35,034 + 6,618,656 + 68,297。

新增精确见证计数构建 19,504,271 次，命中已有计数 24,631,030 次。原交集路径调用下降约 98 倍，但新界也要扫描倒排，候选枚举与边证书请求数没有下降，因此总时间只有约 1.80 倍收益。后续值得试验见证倒排的查询内位图化/批量交集，优先减少新界约 43.49 亿次条目读取，并将其构建时间完整记入在线；不能直接据调用数宣称百倍加速。
