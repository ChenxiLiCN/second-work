# SECI 算法设计与本机实验

## 1. 设计目的

SECI（Selective Equivalence Certificate Index）用于处理 FLI 在线求交过慢、全量 SCI 又接近重新存储投影图的稠密元路径。它优先优化在线时间，同时避免为每条投影边保存一个证书。

当前原型设置系统覆盖下界 `theta_0=0.9`。该值是离线索引的覆盖策略；在线用户仍输入 `epsilon` 和 `mu`。当 `epsilon >= theta_0` 时结果精确地由 SECI 回答；当 `epsilon < theta_0` 时不能把缺失边当作不相似，必须回退 FLI，或由更低覆盖层回答。

## 2. 离线算法

1. 对每个目标类型顶点取得元路径投影的闭邻域。
2. 对闭邻域做双哈希，并在哈希桶内逐项比较，只有闭邻域完全一致的顶点才归入同一等价类。
3. 每个等价类只保留一个代表顶点；类内任意两点的结构相似度恒为1，因此类内边无需逐条存储。
4. 从代表邻域生成商图类边。若两个类相邻，则它们之间是完整二部关系，一条类边可代表两个类之间的全部顶点边。
5. 对类边先应用精确度数比上界。不能达到 `theta_0` 的类边直接丢弃。
6. 对剩余类边计算闭邻域公共顶点数；计算过程中使用“当前公共数 + 最大可能剩余公共数”做安全的提前终止。
7. 只保留相似度不低于 `theta_0` 的类边证书，并按精确临界相似度降序排列。

索引保存等价类成员、类闭邻域度数，以及选择性类边三元组 `(class_u, class_v, common)`。它不保存1.5 GB的投影邻接表。

## 3. 在线算法

1. 检查查询 `epsilon >= theta_0`。
2. 在按临界相似度排序的证书上二分，得到本次查询的相似类边前缀。
3. 类内对每个顶点隐式贡献 `class_size-1` 个相似邻居；每条相似类边给两侧顶点分别贡献对方类大小。
4. 按 pSCAN 的 `mu` 判定核心类。
5. 在核心类之间执行并查集合并；簇编号取连通分量中的最小原顶点编号。
6. 将非核心类连接到相邻核心簇，并按 pSCAN 语义输出 core、border、hub 和 outlier。

聚类逻辑没有替换 pSCAN，只是把逐顶点边运算等价地提升到了带权商图上。

## 4. 正确性要点

- 同一等价类中的顶点闭邻域相同，所以度数、与任意外部类的邻接关系和结构相似度都相同。
- 两个相邻等价类之间构成完整二部关系，因此一条带权类边可以精确恢复每个顶点的相似邻居数量。
- 被度数比上界或覆盖下界排除的类边，在任意 `epsilon >= theta_0` 时都不可能成为相似边。
- 证书保留精确公共邻居数，因此提高在线 epsilon 时只需选择更短前缀，不需要近似判断。

## 5. Yelp 本机结果

- 数据：Yelp，元路径 `U-R-B-R-U`，522,139个目标顶点，187,650,023条投影边。
- SECI：138,139个等价类，905,765条保留类证书，文件14,062,936字节。
- 构建：读取已有物化图时30.474秒。
- 查询：`epsilon=0.9, mu=5`，20次端到端平均231.67毫秒，中位数228.82毫秒。
- 加速：相对旧 HINSCAN 完整流程550.89倍，相对原 FLI 在线算法393.67倍。
- 正确性：0.9和0.95两组簇结果均与原 pSCAN 文件哈希完全一致；0.9的角色文件也完全一致。

## 6. DBLP、Movies 与 IMDB 小规模实验

为了在服务器不可用时继续验证，使用本机已有物化基线图构建覆盖下界为0.5的 SECI。在线时间采用完整端到端口径，包含进程启动、索引读取、聚类以及簇和角色文件写出，每组重复30次。

| 数据与元路径 | 投影边 | 等价类 | 保留类证书 | 构建时间 | 索引大小 | 在线平均 / 中位数 | 相对旧完整流程 |
|---|---:|---:|---:|---:|---:|---:|---:|
| DBLP `A-P-A` | 43,339 | 12,492 | 11,555 | 7 ms | 311,784 B | 19.14 / 17.97 ms | 4.70x |
| Movies `A-M-D-M-A` | 352,600 | 7,736 | 43,261 | 259 ms | 621,620 B | 16.05 / 15.66 ms | 21.74x |
| IMDB `A-M-D-M-A` | 6,550,895 | 47,407 | 648,341 | 10.553 s | 8,559,584 B | 84.26 / 84.02 ms | 93.97x |

三组数据各自的簇文件和角色文件均通过 SHA-256 校验，合计6/6与原 pSCAN/精确 FLI 结果完全一致。DBLP 和 Movies 的运行时间已经接近 Windows 进程启动及文件输出下限，SECI 的主要收益体现在 IMDB：相对当前 UPI/SCI 的119.19毫秒进一步降到84.26毫秒，同时单路径索引仅8.56 MB。

为测试覆盖范围，另外在 IMDB 上构建 `theta_0=0.3` 的 SECI。该索引构建16.457秒，保留2,800,135条类证书，文件34,381,112字节。同一索引可回答0.3以上的所有 epsilon，四组簇结果均与原 pSCAN 完全一致。

| epsilon, mu | 相似类边前缀 | 20次端到端平均 | 中位数 | 簇一致 |
|---|---:|---:|---:|---|
| 0.3, 2 | 2,800,135 | 204.89 ms | 202.48 ms | 是 |
| 0.5, 5 | 648,341 | 193.09 ms | 192.69 ms | 是 |
| 0.7, 5 | 92,003 | 184.41 ms | 183.52 ms | 是 |
| 0.9, 2 | 7,219 | 191.84 ms | 186.32 ms | 是 |

降低覆盖下界会扩大索引并增加加载时间：IMDB 的0.3覆盖层为34.38 MB，而0.5覆盖层仅8.56 MB。因此正式算法不应无条件建立最低阈值的单层索引，而应由空间预算选择覆盖层；高阈值查询优先读取更小的高覆盖层。

## 7. 当前边界与下一步

SECI 已增加直接从 FLI 构建的入口，并接入 UPI 离线构建与在线自动路由。对 DBLP、Movies 和 IMDB，FLI 直建版本与物化图版本的等价类数、商图边数、保留证书数和文件大小逐项一致，三组查询结果也一致。因此物化图现在只用于基线对照，不再是 SECI 构建的必要输入。

UPI 当前路由顺序为：强压缩 EQI、满足覆盖范围的 SECI、SCI、FLI。SECI 与 SCI 共用可配置空间预算；稠密度至少为 `projected_edges >= 16 * vertices` 的路径才尝试 SECI，避免小图被不必要地替换。查询低于 SECI 覆盖下界时直接跳过该文件并回退下一层。

SECI 文件格式已升级为v2连续布局，将类度数、类大小、扁平成员和类证书分段批量读取。IMDB内部加载由约42毫秒下降到约4毫秒，30次端到端平均由82.87毫秒下降到52.74毫秒；文件仍为8,559,584字节。加载器继续兼容已有v1文件。

随后应增加多覆盖层，例如较低阈值层配合更严格的空间预算，并将当前按顶点收集闭邻域的过程进一步改造成分块/外存方式，以控制超大数据集离线构建的峰值内存。覆盖层不影响结果正确性；没有覆盖到的查询必须明确回退，不能近似返回。
